01 — Introduction

What FEILIAN is

FEILIAN is a candidate submitted to the Next-generation Commercial Cryptographic Algorithms programme (NGCC-CH) under the designation hash-10. It runs a 1024-bit chaining state with a 1024-bit message block; the compression function is a tweakable ARX permutation under a Davies–Meyer feed-forward. All three digest lengths reuse the same 1024-bit internal state — only the output is truncated — so one core implementation serves the whole family.

The design in four views

Four views of the same object, redrawn from the specification's own figures. Compression function — the block diagram of FEILIAN-f: five phases, one 1024-bit message block absorbed by all of them, the tweak folded in at every round, and the Davies–Meyer feed-forward. One round — the 4×4 state matrix walking SubColumn → ShiftRow → SubColumn → ShiftRow → AddConstant. SubColumn — the two stacked tweakable ARX S-boxes and the tweaks they exchange. ARX S-box — the add-rotate-XOR network the whole family is built from.

Performance

Chapter 5 of the specification reports the cost of the family: operation counts, memory footprint, software timings on three platforms and FPGA synthesis. The three views below are its reported values — nothing on this page was benchmarked, synthesised or otherwise measured locally. In cycles per byte FEILIAN-1024 settles essentially level with SHA-512 on long messages, ahead of SHA-3-512 and behind BLAKE-64.

05 — Erratum

The designers' erratum: v1.0 → v1.0.1

On 8 October 2026 the designers released specification version 1.0.1 together with a three-page erratum that records every change made to the June 2026 text. The erratum is not reproduced on this page, but it is published on its own beside it and can be opened directly below. Its opening sentence is the one that matters most, and it is quoted verbatim: “The design of hash function FEILIAN does not change. All details should refer to the reference code that illustrates FEILIAN fully and correctly.”

Three short pages — what they contain

The erratum is short enough to read whole. No round, constant, counter rule or iteration count is altered by v1.0.1, and it has three parts.

  • Table 1 — four typographical corrections in the specification: the seventh IV word, the word order of the AddConstant row, a bibliography key, and the printed Appendix B.2/B.3 vectors for FEILIAN-768/512. Both design-affecting corrections were already what the reference code did; the printed text carried the older value.
  • Table 2 — corrections to the implementations, grouped into software and hardware: proper handling of exceptional execution situations, masking of non-full-byte input, allocation, length-representability and digest-length checks in software; and in hardware the current block length included in the 1SC/4SC/8SC compression input, transaction-consistent latching of block, final flag and cumulative length, one counter-word order across all RTL cores, and digest output restricted to completed hashes.
  • §3 — five further text changes made after reading the community assessments, among them writing the counter convention out explicitly (t0 the high word, t1 the low word) and clarifying that the XOF is a variable-output-length hash function.

The erratum is published on its own as well, so it can be read without taking the whole archive: files/FEILIAN_Erratum.pdf, byte-identical to the copy at the top level of the release package, beside the specification. Its SHA-256 begins 98e74ec289636cea…; the full digest, and the digest of the package, are in files/SHA256SUMS.txt.
