01 — Overview

What FEILIAN is

FEILIAN is a candidate submitted to the Next-generation Commercial Cryptographic Algorithms programme (NGCC-CH). It runs a 1024-bit chaining state with a 1024-bit message block; the compression function is a tweakable ARX permutation under a Davies–Meyer feed-forward. All three digest lengths reuse the same 1024-bit internal state — only the output is truncated, so one core implementation serves the whole family.

Design highlights

  • HAIFA-style iteration with a public tweak (§3.1, §4.3)
  • Davies–Meyer: h′ = v₀ ⊕ v₅ = E(h) ⊕ h (§2.2.4)
  • Permutation E: 20 rounds / 5 phases, 2 SubColumn layers per round
  • Strictly ARX — no message-word re-ordering, no linear expansion (§3.1)
  • Six rotation constants in total: 5, 48, 8 and 11, 40, 63 (§3.1)

Public tweak tw=(ver,flag,t₀,t₁)

  • Version ver — 64-bit: 0x200/0x300/0x400 for 512/768/1024
  • Final-call flag flag — 64-bit, 0 or all-ones
  • Counter t — 128-bit message-bit count, split t₀‖t₁
  • Loaded into state row 3 by AC (§2.2.2)

03 — Pipeline

Compression, step by step

Step through the five phases of the permutation E. Each phase holds four rounds: one message-bearing round (dark) and three message-free rounds (light). Message blocks are injected at the first round of every phase, so the last injection is round 17.

Press Play to walk the 20 rounds

Compression wrapper

The chain value h and message block m drive five phase calls v₁=P₀(v₀,m) … v₅=P₄(v₄,m); the output is h′ ← v₀ ⊕ v₅. The tweak binds version, final-block flag and the 128-bit counter into every compression, so the same block processed at a different position is a different computation (§2.2.4, §4.3.2).

Why the counter matters

Under zero-only padding there is no in-block length delimiter, so the processed-bit count carried in the tweak t is what makes the message-to-transcript encoding injective. Encoding the number of processed bits invalidates the expandable-message structures behind Kelsey–Schneier second-preimage attacks (§4.3.2).

Structure and diffusion (§4.3–§4.6)

  • Mode. A HAIFA variant using a counter but no salt; the final-block flag replaces traditional padding's role, giving resistance to length extension and long-message second preimages (§4.3.2).
  • Indifferentiability. §4.3.1 gives a simulator proof with distinguishing advantage O(q²/2ⁿ), arguing that flag makes message processing prefix-free.
  • Davies–Meyer. Collision and preimage resistance from the ideal-cipher assumption; a fixed-point property exists but the designers judge it without real impact (§4.4).
  • Diffusion. Best one-round differential trail 2⁻³; average flipped bits per word after three rounds 31.7–32.4 out of 64 (§4.5.3, Table 4.3).
  • Dedicated attacks. Rotational, slide, rotational-slide, meet-in-the-middle and boomerang analysis (§4.6); four phases are argued sufficient against sliding, because aligning P₀ with P₄ requires sliding over four phases.

Vectorisation techniques (§5.2)

  • Each 4-word row packed into one 256-bit AVX2 register — four lanes per instruction.
  • Byte-granularity rotations via VPSHUFB with static masks, replacing shift/shift/or.
  • ROT63(x) = (x≫63) ⊕ (x+x), using the add unit instead of the shift unit.
  • All 20 rounds explicitly unrolled as five blocks of four.
  • Feed-forward from registers holding the initial state; no reload from memory.
  • Dual state buffers with pointer swapping, plus two-block-ahead non-temporal prefetch.

Parallelism (§5.1.3)

  • Four independent SubColumn calls per SubMatrix — 4-way column parallelism, with no cross-column dependency until ShiftRow.
  • Within a SubColumn the first two additions are independent, as are the two rotations inside each Σ.
  • A column is 256 bits wide, so it maps exactly onto one AVX2 register; 512-bit units are not twice as column-efficient but can hash two messages in lockstep.
  • ShiftRow needs cross-register shuffling, which the specification flags as a potential latency cost on some microarchitectures.

08 — Applications

MAC, KDF and XOF

Chapter 6 builds three standard constructions on the indifferentiability claim, exploiting the built-in counter and final-block flag.

MAC (§6.1)

Because the flag and counter make length extension infeasible, a prefix-key MAC is available without HMAC's nested hashing:

MAC_K(M) = FEILIAN(K‖M)

Secure up to 512-bit, the birthday bound of the 1024-bit state; the specification says it suits FEILIAN-512 in particular. HMAC over FEILIAN is the alternative given wide HMAC deployment.

KDF (§6.2)

An extract-then-expand fit for HKDF-style constructions:

PRK = FEILIAN(IKM)
K_i = FEILIAN(PRK‖info‖i)

Each K_i is a fresh oracle output on a distinct input, so the derived keys are pseudorandom and mutually independent; output length is unbounded in i.

XOF (§6.3)

Absorb and squeeze are separated by the ver and flag words, with the counter re-initialised to 0:

Out₀ = f(h_root, empty, t=0)
Out₁ = f(h_root, empty, t=1)
XOF(M) = Out₀‖Out₁‖…

09 — Components

Component-level linear-structure analysis

A companion paper (Cryptology ePrint 2026/2236, CC BY 4.0) gives a complete classification of the whole-output linear structures of the 64-bit SubColumn. The paper states plainly that its results are component-level and establish no hash attack and no bound on the hash's security margin.

Result for FEILIAN

  • For w=64, r=8, s=63: LD(F) = S, dimension 2.
  • Exactly three nonzero members (M=2⁶³):
    (0,M,0,M)→(M,0,M,0)
    (M,0,M,M)→(M,0,0,0)
    (M,M,M,0)→(0,0,M,0)
  • Beyond the two SubColumn boundaries the family dies: LD(A∘R∘A)∩LD(A)={0}.
  • Real FEILIAN (ShiftRow B=I) lands in the first census row (8→0) — the family is cleared at the second boundary.
